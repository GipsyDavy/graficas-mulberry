Política de duplicados: omitir, actualizar o crear nuevo

Cuando importas un archivo que contiene registros cuya clave (NIF, DNI, número…) ya existe en la base de datos, el sistema aplica la política de duplicados que hayas elegido en el diálogo de mapeo.

Opciones disponibles

OpciónDescripciónCuándo usarla
Omitir si existe
(por defecto)		 Si la clave ya existe en la BD, esa fila se descarta sin error. Solo se importan los registros nuevos. Primera importación de datos históricos. Cuando los datos de la BD están actualizados y no quieres sobreescribir nada.
Actualizar existente Si la clave ya existe, se actualizan los campos del registro con los valores del archivo. Si no existe, se inserta como nuevo. Actualización masiva de datos ya importados (p. ej. cambio de tarifas, actualización de stock).
Crear siempre Se inserta un registro nuevo independientemente de si la clave ya existe. El sistema genera una clave nueva. Solo para datos sin clave natural única. No usar para clientes, materiales o empleados.
La opción Actualizar existente sobreescribe los campos del registro existente. Los campos que no vengan en el archivo quedan sin cambios, pero los que sí vengan se sobreescriben aunque el valor sea vacío. Haz un backup antes de usarla. Ver Qué campos sobreescribe la política Actualizar.
La opción Crear siempre no está disponible para módulos parent-child (Presupuestos, Facturas, Albaranes). Estos módulos usan el número de documento como clave y deben ser únicos.

El resumen de importación

Al finalizar la importación, el sistema muestra un resumen con:

  • Insertadas — registros nuevos añadidos.
  • Actualizadas — registros existentes modificados.
  • Omitidas — registros descartados por duplicado (con política Omitir).
  • Errores — filas con problemas que no se pudieron procesar.
